# فعال‌سازی تغییرات حساب

تغییرات ظاهری با انتشار سایت فعال می‌شوند. تغییر نام کاربری، بازیابی با نام کاربری و تیکتِ بدون ورود به نصب سرور نیاز دارند.

۱. در Supabase پروژهٔ upwbktvnybsjugdegjji، از منوی سمت چپ SQL Editor را باز کنید و New query بزنید.
۲. تمام فایل setup_services.sql را کپی و Run کنید. این فایل کاربران یا مطالعه‌ها را حذف نمی‌کند.
۳. برای نام مدیر، فایل rename_owner_drgerami.sql را در یک New query اجرا کنید. UUID، ایمیل و رمز قبلی حفظ می‌شوند.
۴. در Edge Functions یک تابع با نام intmed-recovery بسازید، متن functions/intmed-recovery/index.ts را جایگزین کنید، Verify JWT را خاموش و Deploy کنید. کلیدهای پیش‌فرض Supabase در محیط تابع وجود دارند؛ چیزی در چت نفرستید.
۵. در سایت، بازیابی با نام کاربری خود را آزمایش کنید. لینک فقط به ایمیل تأییدشده می‌رود. تیکت‌های بازیابی در تب مدیریت دیده می‌شوند؛ پاسخ در پنل ذخیره و از طریق برنامهٔ ایمیل ارسال می‌شود، ارسال خودکار ایمیل پشتیبانی هنوز فعال نیست.

## حذف حساب‌های اضافه

فایل cleanup_memberships_keep_owner_test.sql جداست و در نصب عادی اجرا نمی‌شود. داده‌های مطالعهٔ حساب‌های حذف‌شده نیز حذف می‌شوند. این فایل فقط عضویت IntMed را حذف می‌کند و به حساب‌های Auth مشترک با برنامه‌های دیگر دست نمی‌زند. حساب Auth باقی‌مانده ممکن است با همان ایمیل نیازمند بازیابی و فعال‌سازی مجدد عضویت باشد؛ ثبت‌نام مجدد آن تا ساخت مسیر بازیابی عضویت تضمین نشده است. پیش از اجرا خروجی SELECT ابتدای فایل و نسخهٔ پشتیبان را بررسی کنید. یک مدیر و دقیقاً یک کاربر test باید وجود داشته باشد؛ در غیر این صورت هیچ چیز حذف نمی‌شود.

این مراحل از محیط توسعه بدون دسترسی مدیریتی Supabase قابل اجرا نیستند. هیچ حذف یا تغییر نامی صرفاً با انتشار کد اتفاق نمی‌افتد.
