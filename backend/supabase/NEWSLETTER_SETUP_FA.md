# راه‌اندازی خبرنامهٔ ایمیلی IntMed

پنل و کد آماده‌اند؛ تا پایان مراحل زیر ارسال واقعی فعال نیست. کاربران قدیمی خودکار عضو نمی‌شوند.
کلید Resend و کلید امضا را فقط در Secrets خود Supabase قرار دهید، هرگز در چت، GitHub یا فایل config.js.

## ۱. ساخت سرویس ارسال

1. در https://resend.com حساب بسازید.
2. در Domains، دامنهٔ `drgerami-md.ir` یا زیردامنهٔ اختصاصی ارسال را اضافه کنید.
3. رکوردهای DNS را دقیقاً با نام و مقداری که خود Resend می‌دهد، در پنل دامنه وارد کنید.
   مقدار رکوردها را حدس نزنید. منتظر وضعیت Verified بمانید.
4. در API Keys، یک کلید مخصوص ارسال بسازید؛ در صورت امکان دسترسی را به همان دامنه محدود کنید.
   مقدار را فقط برای ورود در Supabase نگه دارید. شرایط و سقف پلن را از Pricing خود Resend بررسی کنید.
5. یک نشانی فرستنده از دامنهٔ تأییدشده انتخاب کنید؛ مثلاً `IntMed <updates@drgerami-md.ir>`.
   این مثال فقط پس از تأیید همان دامنه معتبر است. برای پاسخ کاربران، از نشانی‌ای استفاده کنید که دریافت آن را مدیریت می‌کنید.

## ۲. نصب جدول ثبت ارسال

1. پروژهٔ موجود IntMed را در Supabase باز کنید.
2. از منوی چپ **SQL Editor** و سپس **New query** را بزنید.
3. تمام محتوای فایل [newsletter.sql](./newsletter.sql) را کپی کنید و Run بزنید.
4. باید پیام موفقیت بگیرید. این فایل جدول‌های قبلی یا اطلاعات کاربران را حذف نمی‌کند.

## ۳. تنظیم سه مقدار محرمانه

در **Edge Functions → Secrets**، این سه مورد را اضافه کنید:

- `RESEND_API_KEY`: همان کلید ارسال Resend.
- `NEWSLETTER_FROM`: نام و ایمیل فرستندهٔ تأییدشده.
- `NEWSLETTER_SIGNING_SECRET`: یک رمز تصادفیِ مستقل، دست‌کم ۳۲ کاراکتر، از مولد رمز مدیر رمزهای خودتان.
  رمز حساب، کلید Supabase یا کلید Resend را برای این مورد تکرار نکنید. تغییر این مقدار لینک‌های لغو عضویت قدیمی را نامعتبر می‌کند.

مقادیر استاندارد `SUPABASE_URL`، `SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY` را محیط Edge Function تأمین می‌کند؛
`service_role` را داخل کد یا مرورگر کپی نکنید.

## ۴. نصب تابع از مرورگر

1. **Edge Functions → Deploy a new function → Via Editor** را انتخاب کنید.
2. نام را دقیقاً `intmed-newsletter` بگذارید.
3. کد [index.ts](./functions/intmed-newsletter/index.ts) را کامل جایگزین کد نمونه کنید و Deploy بزنید.
4. برای **همین تابع** گزینهٔ Verify JWT را خاموش کنید تا لینک عمومیِ امضاشدهٔ لغو عضویت کار کند.
   درخواست‌های مدیریتی در خود کد با Auth و نقش مدیرِ فعال کنترل می‌شوند؛ تنظیم دیگر توابع را تغییر ندهید.

## ۵. اولین ارسال

1. در سایت با حساب مدیر وارد شوید: داشبورد → مرکز مدیریت → خبرنامهٔ ایمیلی.
2. «بررسی اتصال ایمیل» را بزنید.
3. عنوان و متن کوتاه خبرنامه، همراه لینک مستقیم مطالب، وارد کنید.
4. «پیش‌نمایش و تعداد گیرندگان» را بزنید؛ این مرحله چیزی ارسال نمی‌کند.
5. «ارسال آزمایشی فقط به مدیر» را بزنید و ایمیل، فرستنده و لینک لغو عضویت را بررسی کنید.
6. پس از بررسی، «ارسال به حداکثر ۲۰ مشترک بعدی» را بزنید و پیام تأیید را بخوانید.
   اگر مشترک بیشتری باقی مانده بود، برای همان خبرنامه دوباره همان دکمه را بزنید.
7. تا پایان ارسال، عنوان/متن را عوض نکنید. شناسهٔ نوبت در همان تب مرورگر حفظ می‌شود؛ رفرش همان تب آن را نگه می‌دارد، ولی عنوان و متن را باید دوباره وارد کنید.
   برای ادامهٔ همان خبرنامه از تب جدید استفاده نکنید. دکمهٔ «خبرنامهٔ جدید» عمداً نوبت تازه می‌سازد و می‌تواند همان متن را دوباره ارسال کند.

هر ایمیل فقط به یک گیرنده می‌رود؛ آدرس دیگران نمایش داده نمی‌شود. فقط حساب فعال، رضایت فعلی و ایمیل منطبق
با ایمیل تأییدشدهٔ Auth ارسال می‌گیرد. لغو عضویت از حساب یا لینک انتهای ایمیل ممکن است؛ GET لینک فقط
صفحهٔ تأیید را نشان می‌دهد تا اسکنر ایمیل عضویت را ناخواسته لغو نکند. درخواست POST امضاشده لغو را ثبت می‌کند.

ثبت یکتای نوبت/کاربر جلوی تکرار همان ارسال را می‌گیرد. ارسال ناموفق یا مبهم خودکار تکرار نمی‌شود؛ پیش از
هر تکرار، Logs در Resend و جدول خصوصی `intmed_newsletter_deliveries` را بررسی کنید. اگر ارسال موفق بوده
ولی ثبت نتیجه قطع شده باشد، وضعیت processing باقی می‌ماند تا از ارسال تکراری جلوگیری شود.

این نسخه صف زمان‌بندی‌شده یا ارسال کاملاً خودکار پس از هر انتشار نیست؛ مدیر متن را بررسی و ارسال را آغاز می‌کند.
